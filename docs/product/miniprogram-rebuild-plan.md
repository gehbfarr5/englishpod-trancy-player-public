# 微信小程序重建实施方案
编号：EP-MP-REBUILD-001 · v0.1 · 2026-10-24（北京时间）
状态：方案草案，待审阅；本轮只制定方案，不启动全面重写或发布。

## 1. 基础与变更边界
用户已审阅并授权合并 PR #35 的产品规格。规格中标为“已确认”的决策生效；候选和待验证项不会因为文档被审阅而自动全部批准。
参见 [产品规格](miniprogram-v1-product-spec-draft.md)、[行为基线](playback-behavior-contract.md)。
目标：以微信平台支持的方式重新实现课程学习。每课只有 PB 音频，PB/DG 台本和单词可查看；切展示不干预声音。
不修改 Flutter iOS/Android/Web 行为，不删除 DG 云端资源，不新增账号同步、离线下载或运营系统。
旧代码作为问题和数据契约的参考，不以“先删 DG 再不断修补旧页面”为实施路线。

## 2. 总体实施策略
按“官方能力核验 → 最小音频实验 → 音频与进度核心 → 内容界面 → 自用验收”推进。
先证明关键播放链路，再开发完整页面。保留现有 main/版本作基线，在独立实现分支重建；旧页面仅在新版本通过验收后替换，避免新旧两套音频同时初始化。
实现目录的最终安排在 M1 定稿；建议独立目录开发后一次受控替换，不长期保留双套产品或维护复杂运行时开关。
复用已经验证且仍适用的交付基础，不重建仓库、云环境和上传系统。

## 3. 微信官方规范核验门槛（M0）
每一能力必须有证据表：需求、官方链接/章节、查阅日期、适用基础库/客户端/系统/渲染器、确认的能力、限制、失败方案、实验和结果。
官方类型定义仅能支持接口签名/注释事实；不得用它替代运行机制指南或真机结果。官方页面无法读取时保持“待核验”，不写“兼容审查通过”。
优先核验：
1. BackgroundAudioManager 生命周期、换 src 自动播放、startTime/seek、当前时间/时长、倍速、系统控制与中断、前后台回调。
2. 小程序前后台运行机制、页面隐藏/卸载、冷启动/热返回与后台音频继续的关系。
3. setData 性能、组件数据边界、scroll-view、节点测量、WebView/Skyline 支持范围。
4. 网络域名/音频 URL 有效期、后台音频声明、分享参数、存储限制与失败行为。
具体官方入口见产品规格 §5。第三方经验仅作排查线索。
退出门槛：核心能力证据完整；不完整项目有明确阻塞范围。发生冲突应记录“哪条产品规则/哪条平台限制/复现实验/替代方案”，不能自行删除规则。

## 4. 建议模块边界（M1 后定稿）
| 模块 | 职责 | 明确禁止的耦合 |
| --- | --- | --- |
| CourseRepository | 目录/详情读取、内容校验、缓存与错误 | 不操作播放器或完成记录 |
| PodcastSession | 应用级 PB 音频会话、用户意图、当前课/状态 | 不由 tab 切换创建/销毁，不依赖页面滚动 |
| WeChatAudioPort | 封装官方后台音频事件和命令 | 不包含台本布局或学习完成策略 |
| PlaybackPolicy | 入口、手动切课、连播、完成判定 | 不用计时器估算冒充真实播放完成 |
| ProgressRepository | 有效断点/完成事实/最后打开课程、写入顺序 | 不接收无课程归属的裸时间，不被旧回调覆写 |
| ContentView | PB/DG/单词展示、阅读位置 | 不持有第二套媒体引擎 |
| TranscriptFollow | 仅在可见 PB 台本上协调高亮/跟随 | 不拿 DG 时间戳直接映射 PB，不驱动声音 |

状态拆分：
- 音频：idle/loading/playing/paused/ended/error；用户最新意图独立保存，异步结果带有效代次。
- 学习记录：课程完成事实与 PB 有效断点分离；临时 00:00 不立即覆盖历史。
- 界面：selectedContent=podcast/dialogue/vocab，与 activeAudio=podcast 独立。
后台无需维护不可见台本动效；回前台读取可用的真实媒体状态再协调。不能预设后台 JS 持续运行。

## 5. 复用与重建清单
| 现有内容 | 处理建议 |
| --- | --- |
| 课程 ID、索引、内容模型、云端 PB/DG 文本和词汇 | 核对字段和数据质量后复用；不删除 DG 数据 |
| 课程读取服务和 URL 解析 | 审查缓存、过期、错误/取消语义后按需复用 |
| GitHub CI、预览/上传链路 | 保留；先核对当前实际运行状态、保护规则及产物来源 |
| 进度保存、完成判定的纯逻辑和测试 | 保留仍适用的行为测试；实现是否复用逐模块评估 |
| 旧双轨状态机、DG 音频记录、切轨镇定窗口 | 新小程序不继承其双轨复杂性 |
| 大型播放器页面、滚动估算/逐帧补偿链 | 按新模块重新实现，只有经最小实验证明必要的机制才引入 |
| 主题配色与基础视觉资产 | 可复用；不承担复刻 iOS 动效的要求 |
不能把测试数量或代码复用率当作成功指标。

不承诺未经 M1 估算的完成日期；M1 后按模块工作量提供范围和依赖，不虚构工期。

## 8. 验证与阻断条件
复用产品规格 MP01–MP11 并补充：
- 一次有效播放会话：切三个内容、返回列表、再次进入当前课都不得无意重载或双音频。
- 冷启动静音与后台已有音频的热返回分别验收。
- 按正常播放、主动 Seek、初始化恢复三类事件验证 95% 完成；不使用墙钟外推当完成证据。
- 断点/完成写入乱序、失败、加载中离开及 A→B→C；旧事件不能触发错课/开播。
- 后台持续播放、后台自然结束连播、末课回第一课、下一课失败分开测试。
- 实际声音与高亮错位要分别检查原始时间戳、媒体位置采样、渲染更新、滚动，先定位再修。
- 性能记录首个可用内容、首播、控制响应、长台本滚动、setData 频率/载荷。阈值先测量再定，精确滚动曲线不是目标。
- 所有设备结果记录版本/SHA、基础库、微信/系统/设备、网络、步骤、PASS/FAIL/NOT TESTED；未执行不能勾通过。
阻断自用候选：播放状态错误、内容切换影响声音、断点丢失/回退、错误完成、旧请求开播、前后台返回导致音频重载、未处理的核心官方限制。
阻断对外开放：核心 Android 实机未验、分享入口或首次学习流程未验、未解决的数据/课程加载问题。

- M2/M3 运行小程序类型/测试/配置检查及相关 CI；只写 meaningful 行为回归，不重复实现细节。
- 构建上传依照现有链路，记录源码 SHA/版本/Run；不绕过分支保护，不把 CI 当作设备验收。
- 旧版本保留可追溯引用；新存储使用明确 schema/命名空间，未经授权不清除旧记录。
- 本次用户授权合并的是 PR #35；新方案在独立 PR 供审阅，不自动合并新实现、提审或公开发布。
