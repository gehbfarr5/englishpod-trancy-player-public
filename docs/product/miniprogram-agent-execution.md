## Agent 修复循环
开发 → 静态/单元/配置检查 → 云端构建上传 → 指定版本云测 → 等待终态 → 读取报告/截图/日志 → 判定产品缺陷或环境问题 → 修复 → 相关回归 → 最终全套适用回归。
- 仅任务提交成功、上传成功、无崩溃或 Monkey 通过，不代表音频/后台/进度场景通过。
- 判断真实出声、音频时间、后台调度的能力必须单独核实。云测未提供证据的项目明确 NOT TESTED/BLOCKED，不用 UI 截图代替声音证据。
- 不循环盲目重跑；可恢复环境错误有限重试，持续失败形成诊断和修复任务。
- 报告必须区分 PASS/FAIL/ERROR/NOT TESTED/N/A；删去 DG 音频的用例记 N/A，但保留三内容切换不干预 PB 的新回归。
- 最终报告引用每项结果所对应的同一候选 SHA；修复后的新 SHA 不能沿用旧版本通过结果冒充当前通过。

## 交付定义
交付的是可供连续使用的完整候选版本，不是只过编译的骨架。至少包含：
1. 已确认的唯一 PB 音轨、两类台本、单词查看、课程入口、进度及完成记录；
2. 适用行为基线和已确定交互的回归结果；
3. 云端 iOS/Android 微信设备覆盖，以及后台/锁屏/中断/弱网中实际可测的场景证据；
4. 有效预览或开发/体验入口、应用版本、源码 SHA、CI Run、云测任务/报告、已知限制与回退方法；
5. 所有核心阻断项解决。若平台或授权阻止完整验收，报告明确缺口，不称“完整验收通过”。
公开发布另行按用户授权执行。

## 需求处理
不重新展开定位、单音轨或既定进度规则。回听、高亮/跟随、循环、分享入口仍需在 A5 形成确定表：Agent 先提出一套与简化目标及基线一致的默认建议，只有改变已确认产品行为、存在多种明显不同结果或官方冲突时才集中向用户确认。
