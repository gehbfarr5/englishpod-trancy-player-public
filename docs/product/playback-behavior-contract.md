## 1. 产品定位和术语

1. **Podcast (PB)**：主学习音轨；默认进入、继续收听、课程完成与自动连播围绕 PB 运作。**Dialogue (DG)**：临时补充音轨；可手动听、手动切课，保存独立位置，但不取得默认入口优先权，也不自然自动连播。[P]
2. **课程完成记录** `lessonCompleted` 与 **当前播放位置** `positionMs` 是独立数据。完成是持久学习事实；位置反映最近一次有效收听/主动 Seek 的断点，可随重听更新。[P]
3. **普通课程列表入口**、**上一课/下一课**、**继续收听入口**、**同课切轨**、**自动连播**是五种独立意图，不能复用含糊的默认参数。[D]
4. **自然结束**表示音频在正常播放过程中到达末尾；手动将进度条拖到末尾、程序初始化 seek 到末尾，不构成自然结束，也不能冒充完成或触发自动下一课。[D]
5. **已打开课程（lastOpenedLesson）**：用户最近明确进入或成功导航到的有效课程，与是否已经真正播放无关。**当前正在播放音轨**与 **PB 断点** 是其他独立字段。[P/D]
6. 「本规范跨平台」指用户可观察到的音频行为与记录语义一致，不表示所有平台 UI、存储实现或后台能力必须相同。[P]

## 2. 入口、切课与切轨：唯一行为矩阵

| 入口或动作 | 目标课程 | 目标音轨 | 位置规则 | 播放状态 | 更新 lastOpenedLesson |
| --- | --- | --- | --- | --- | --- |
| 点击课程列表普通课程项 | 被选课程 | **PB** | 该课未完成则恢复 PB 断点；**已完成则 PB 00:00** | **明确请求播放（含新启动后的首次点击）**；加载中最新暂停意图优先 [P] | 是 [P] |
| 手动上一课/下一课 | 按实际索引相邻课程 | 继承 PB/DG | **00:00** | 继承现有播放/暂停 | 是 [P] |
| PB 自然结束且自动连播生效 | 索引中下一课程；**已是最后一课则第一课** | **PB** | **00:00**（循环目标同样 00:00，不续播其历史断点） | 开始播放 | 目标成功打开后更新 [D] |
| 点击「继续收听」卡片主体 | **最后打开的课程** | **PB** | PB 未完成断点；已完成或无有效断点则 00:00 | **明确请求播放**；已在目标 PB 则不重复加载 [P] | 不改课程锚点 [P] |
| 点击「继续收听」卡片内播放图标 | 同上 | **PB** | 同上 | 请求播放；若已经在目标 PB 播放则无重复加载 | 不改课程锚点 [P] |
| 同课 PB ↔ DG 选项卡 | 当前课程 | 用户点击的音轨 | **恢复目标音轨自身有效断点**；无断点/已自然结束则 00:00 | 继承现有播放/暂停 | 仍是当前课程 [P] |
| 切换 Vocab | 当前课程 | **底层音轨不变** | 底层音频位置不变 | 不主动暂停或播放 | 不变 [P] |
| 刷新或重启浏览器 | 首先显示课程列表 | 「继续收听」卡片指向最后打开课程 **PB** | 最近成功保存的 PB 断点，完成则 00:00 | **不自动发声** | 不新增访问事件 [P] |

- **课程完成条件只受 PB 影响**，DG 任何播放事件不得改变 `lessonCompleted`。[P]
- **同一课程的 PB、DG 断点独立保存**。DG 临时切换不会清零 PB 断点。[P]
- **课程列表普通进入 PB** 即使目标最后一次收听的是 DG；**继续收听也 PB**，这是明确的产品取舍，不恢复 DG 作为默认音轨。[P]
- 手动切课时 **关闭单句循环、保留当前音轨循环、自动连播保持原值**；同课切轨同理。[P]（不提供自动连播开关的端该值恒为开启，见 §3.2）
- 第一课「上一课」与最后一课「下一课」**手动按钮**禁用；手动导航依据**实际课程索引**、**不循环首尾**。**自然结束的自动连播不受此限**：最后一课 PB 自然结束后循环回第一课（§3.2 第 3 条、F09）。这两件事必须分开实现，不得用手动导航的边界规则去拦自动连播。[P]
- **首次从未打开任何课程**：继续收听区域应呈初次收听引导/默认第一课 PB 00:00，不伪造历史断点。[D]

### 2.1 关键区别：最后打开，不代表修改历史断点

示例：Lesson 012 PB 上次听到 08:45；用户手动导航到 Lesson 025 DG，尚未开始播放就退出：

- `lastOpenedLesson = 025`（更新「继续收听」目标）；
- Lesson 025 PB 原有断点若为 06:10，则「继续收听」恢复 **Lesson 025 PB 06:10**；若无有效 PB 断点则 00:00；
- Lesson 012 PB 的 08:45 保留；仅打开新课不把其他历史记录清空。[P/D]

### 2.2 「继续收听」与同次会话正在播放 DG 的交叉情况

v1.3 确认：普通列表、继续收听主体/播放图标均是用户明确的播放入口；页面启动本身不是播放入口。[P]

- 卡片是一个**明确的 PB 恢复入口**，不只是没有目标的普通导航。若当前活跃音轨为 DG，点击卡片主体需切换至该课程 PB 的有效断点，并**请求播放**（DG 播放或暂停均切至 PB 有效断点后播放）；加载期间新的暂停意图仍优先。
- 由于切换了实际媒体文件，加载期间可能短暂静音；这不属于故意暂停，也不得并行出现两条音频。若已经在目标 PB 上且音轨处于有效播放/暂停位置，卡片主体导航并请求播放，不重新加载，也不将内存中的实时位置倒退到较旧的持久化检查点；**例外**：若当前只是手动切课形成的「未开始播放的临时 00:00」，而该课 PB 存在旧有效断点，则应在不重新装载音频的前提下恢复该断点。这既符合「继续收听」语义，也保护用户当前真实收听的状态。
- 卡片的**播放图标明确请求播放**，不会因为「toggle」语义将正在播放的 PB 反而暂停；卡片主体与播放图标必须隔离点击事件。
- 页面刷新/重启前后不延续 `playing=true`，在课程列表保持静音；用户点击普通课程、卡片主体或播放图标进入后请求播放。浏览器拒绝时按 §5.1 等待真实点击，不绕过限制。

## 3. 完成判定、单句循环、音轨循环与自动连播

### 3.1 完成记录 [P]

- **只由 Podcast 决定整课完成**；Dialogue 的结束不改变 `lessonCompleted`。
- 触发完成的两种有效情形：**正常播放跨越 PB 时长的 95%**；或 **PB 在真实连续播放过程中自然结束**。
- 单纯 Seek 到 95%/100%、句段跳转、加载时定位至末尾**不得**触发完成。Seek 到 98% 后实际播放到自然末尾，**可以**完成。
- 95% 是标记阈值，不表示要提前停止音频；PB 继续播完，再执行下一步。
- `lessonCompleted` 为**单向持久事实**；一旦 true，不会因从头重听、切轨、失败、返回列表而变 false。新版本不迁移旧测试数据，但新结构创建后的记录必须可靠保存。
- 即使 PB 已 Completed、重听时的实时进度只有 20%，列表仍是 Completed；进度条可以同时表达本次收听位置。[P]

**事件区分 [D]**：播放器必须区分 `playbackProgress`、`userSeek`、`trackNaturalEnded`。仅在「真实 playing 状态下由媒体时间推进跨过 95%」或可信自然结束事件时完成；Seek 到末尾产生的引擎 `completed` 回调必须过滤。保护完成更新的幂等性。

### 3.2 决策优先级 [P]

1. 单句循环：到当前有效句末尾后循环该句；不会向上冒泡为整条音轨结束。
2. 当前音轨循环：当前 PB / DG **自然**结束后从 00:00 重播当前音轨。
3. 自动连播：**仅 PB** 在自然结束后、自动连播生效时，**有下一课**则下一课 PB 从 00:00 开始；**已是最后一课**则**循环回第一课** PB 00:00 开始。
4. 否则停止：PB 在自动连播被关闭时停止（停在末尾、主按钮显示 ↺，点 ↺ 从本课 00:00 重播）；**DG 不论自动连播取值如何，结束即停止**（除非当前音轨循环）。

**首尾循环边界规则（v1.2 新增，[P]/[D]）**

- 触发条件只有一个：**PB 自然结束 + 自动连播生效 + 当前为索引中最后一课**。手动「下一课」按钮在末课仍然禁用（§2），不因本条变为可用；「自动连播关闭」的端（Web/Tesla 关闭开关）在末课仍是停止 + ↺。[P]
- 目标固定为**索引第一课的 PB**，位置 **00:00**：即使第一课存在未完成的 PB 历史断点，也**不从该断点续播**——与第 3 条「自动连播目标恒 00:00」保持同一口径；第一课的历史断点**不被写掉**，只有真实播放推进后才更新（§4.1.3）。[D]
- 该跳转视为**自动连播同类意图**：关闭单句循环、保留当前音轨循环、加载完成后开始播放；加载期间用户若点暂停，**保持暂停**，不被迟到的自动播放覆盖（§5.2）。[D]
- `lastOpenedLessonId` 随循环目标更新为第一课；最后一课在循环**之前**已按 §3.1 置完成并提交末尾断点，循环不撤销完成标记。[P]
- 课程库只有一课：从该课 00:00 重播（等价于音轨循环），不停止、不报错。[D]
- 循环是**持续**的：第一课播完继续第二课……直到用户暂停或退出；不存在「播完一圈后停止」的额外限制。[P]
- **手机端 PB 自然结束不会停在末尾显示 ↺**：它总会进入下一课或第一课。手机端唯一可见的 ↺ 终态来自 DG 自然结束（F05）。[D]
- 单句循环和当前音轨循环**互斥**；开启其一关闭另一个，自动连播的持久值不受影响。
- **自动连播的端差异（v1.1 澄清，[P]）**：手机端（Flutter iOS、Flutter Android、微信小程序）把自动连播作为**固定行为**——恒为生效，**不提供独立开关，也不提供替代控件**（不做提示卡、不做倒计时、不做隐藏手势、不做长按切换）。原因是手机端控制区 UI 空间受限，这是**产品取舍**，不是平台能力限制；对外说明也不得写成「该功能无法实现」。
- **Web（Tesla）**因控制区空间充足提供独立开关，用户关闭后按第 4 条停止；这是当前唯一提供该开关的端。核心逻辑（PB 才连播、目标 00:00、末课循环回第一课）各端完全一致。
- `DevicePreferences.autoNextPodcastEnabled` 在所有端**同构持久化**（首次 `true`）：Web 可读可写；手机端只读且恒为 `true`。保留该字段而不是删除，是为了跨端记录语义一致，以及将来若恢复开关无需变更数据模型。
- 因此**手机端不存在「自动连播已关闭」这个可观测状态**，也**不存在「PB 播完停在末尾」这个终态**：手机端 PB 自然结束总是进入下一课（末课则循环回第一课）。验收时 F08 在手机端记 **N/A（产品简化）**，既不记 PASS 也不记 NOT TESTED。
- DG **绝不自然切到下课 DG，也绝不自行返回 PB**。手动上一课/下一课在 DG 上仍可用，维持 DG。[P]
- 音轨自然结束后，停留在该音轨末尾、显示末句和完成进度；**主按钮显示重播图标 ↺**，点后从 00:00 重播同一音轨，继承当前循环设置。不需要另造一枚重播按钮。[P 对 DG；D 将一致交互用于停止后的 PB]（PB 出现该停止态仅当自动连播被关闭，即 Web/Tesla；手机端 PB 自然结束直接切下一课，见上条首尾循环规则）
- 「已播放完且停止」和「中途暂停」是不同状态：中途暂停的主按钮继续从暂停位置，结束后的主按钮从头播放。[D]
- 最后一课 + 当前音轨循环可继续重复最后一课；末课边界限制针对**跳到下一课程**，不是限制显式重复同一音轨。[D]

## 4. 新版持久化数据模型（无需旧测试版迁移）

**存储域**（字段命名可由各端选择，但语义应等价）：

```text
DevicePreferences:
    schemaVersion
    uiMode = standard | immersive        # Web 小窗口首次 immersive；大窗口不应用、不覆盖此偏好
    sentenceLoopEnabled = false         # Web 开关持久化，切课/切轨关闭规则仍见 §2
    trackLoopEnabled = false            # Web 开关持久化，与单句循环互斥
    playbackRate = 1.0                  # Web 倍速持久化
    autoNextPodcastEnabled = true       # 首次 true；仅 PB 生效；手机端只读、恒 true（§3.2）

LessonLearningRecord[lessonId]:
    lessonCompleted: boolean            # 默认 false；true 后不可自动撤销
    podcast:
        committedPositionMs: integer    # ≥0，限于有效时长内
        committedSegmentIdOrIndex
        durationMs?                    # 可选缓存；变化时校验
    dialogue:
        committedPositionMs: integer
        committedSegmentIdOrIndex
        durationMs?
    updatedAt?                          # 仅用于日志、可选

ResumeAnchor:
    lastOpenedLessonId: lessonId?       # 最后成功打开的课，不是最后实际收听课

RuntimeState:                           # 不要求全部持久化
    activeLessonId, activeTrackId
    playheadMs, playing | paused | loading | ended | error
    entryIntent: library | manualNav | autoNext | resume | trackSwitch
    singleSentenceLoop, trackLoop
    selectedTab: podcast | dialogue | vocab
    followTranscript, visibleReadAnchor
    inFlightLoadGeneration, persistenceRevision
    pendingUncommittedStartFromZero
```

### 4.1 断点写入定义 [P/D]

1. **定期保存 + 关键事件立即保存**：正常播放建议每约 **3 秒**保存一次最新有效位置；暂停、手动 Seek、切课/切轨前、自然结束、触发课程完成、返回列表、可用的后台/页面隐藏事件立即尝试保存。[P；3 秒为推荐可调参数]
2. **只进入课程、只完成音频加载、由于手动切课被定位到 00:00**，不得直接把过去的有效断点覆盖成 00:00。播放头暂时置零，与原已提交断点分离。[P]
3. 从 00:00 **实际开始播放且媒体时间推进**后，新的有效进度方可更新相应音轨的历史断点；显式用户 Seek 是主动改变断点的意图，可以立即保存目标位置，即便保持暂停。[D]
4. 每次保存携带课程 ID、音轨 ID 与**递增的意图/写入版本**；同一逻辑记录的较旧异步写入不能在较新写入后覆盖它。跨课程/音轨保存不得串写。[D]
5. 课程完成标记持久化必须与音轨位置保存**解耦**，确保自然结束/跨 95% 的完成事件不会被稍后的 00:00 重听位置覆盖。[P]
6. 停在末尾的 DG 下次显式进入时从 00:00；已完成 PB 通过普通列表/继续收听进入时从 00:00；有效未完成 PB 则按保存断点恢复。[P/D]
7. `lastOpenedLessonId` 由成功导航/打开的课程更新，**不以是否播放为前提**；失败且从未成功打开课程元数据时不改锚点；不借此覆写播放位置。[P/D]
8. 本地存储写入失败：内存状态仍应可继续使用，后续允许重试；不得谎报「已保存」。不能保证车机进程被系统强杀时毫秒级恢复。[D]
9. 数据可能损坏：以课程 ID 和双轨记录为隔离单元，能读取的有效数据应保留；损坏记录回退为新数据默认值，不传播无效时长或时间。[D]
10. **不做旧测试版兼容或迁移**：新版本从零采用版本化 schema；首次部署时使用新的命名空间或明确的测试数据初始化方案；任何实际清除本地旧测试记录动作事先告知。没有账号级跨设备云同步。[P]

**导航后未播放示例**：上次 PB 断点 08:00 → 通过上一/下一课进入本课显示 00:00 → 不播放直接离开 → 历史断点仍为 08:00，而 `lastOpenedLessonId` 指向此课；下次「继续收听」回到 08:00。若从 00:00 真正开始收听或主动 Seek，才按新位置更新断点。[P/D]

## 5. 加载错误、并发与浏览器限制

### 5.1 错误处理 [P]

- 可恢复的网络超时、临时服务端失败：**有限自动重试**，建议先以额外 2 次作为测试参数，配置整体超时和退避间隔；最终失败**停止并明确提示**，不自动跳课、不暗中换轨、不无限循环。
- 404、无法解码、不支持的格式等明确永久错误：不做无意义的自动重试；提供「重试」和「返回课程列表」。
- 浏览器禁止无用户手势的有声自动播放：进入可恢复的**等待用户点击播放**状态，不视为 404，不用无限请求重试；不要绕过浏览器限制。
- 已完成上一课的永久完成记录不因下一课的加载失败撤销。错误提示不得阻塞基本导航。[P/D]

### 5.2 用户意图与竞态 [D]

- **最后一次有效用户意图优先**：快速 Lesson A→B→C，只允许 C 的异步装载结果更新活动状态；取消或废弃 A/B 的加载、Seek 和重试；旧完成事件不再自动切课。
- 正在自动连播加载下一课时，用户点击暂停、手动选课或手动切音轨，新的操作覆盖先前 `autoPlay` 决定；不得在迟到回调中突然发声。
- 自然结束和手动导航接近同时发生时，避免双重切课/重复写入完成；只有合法当前 generation 可以触发自动下一课。
- 切课或切轨前保存离开音轨的**有效**断点，不得把新课程瞬时的零位置误写到旧课程记录。
- 用户主动播放/暂停的最终意图需跨异步 load 生效，不以请求发起时的布尔值覆盖加载期间的新意图。
- 拖动/手动 Seek 后到末尾出现的引擎 `completed` 信号，不能算「自然结束」或触发 PB 自动连播；下一次显式重播从头开始。
- 不用固定毫秒防抖替代正确的 generation/请求取消与 UI 禁用状态；关键控件在加载中应可预测地反馈状态。

## 6. 浏览器重启、Tesla 跨窗口和 UI 状态 [P]

- Web **小窗口**首次进入播放器默认启用**沉浸偏好**，只有实际播放中才可闲置隐藏；大窗口固定标准布局，不提供沉浸开关、不自动沉浸，也不覆盖保存的小窗口偏好。已有明确标准模式选择必须保留，不用新默认值覆盖。标准/沉浸、自动连播、单句循环、音轨循环的每次开关操作立即持久化，倍速也保存；刷新恢复同一浏览器/原点的有效设置。单句/音轨循环互斥，导航按 §2 关闭单句循环时也保存关闭后的状态；冷启动预加载与进入同一 PB 不得误清已恢复的开关。本节属于 Web/Tesla：自动连播开关**只在此类端提供**；手机端固定开启、无开关（§3.2）。
- 浏览器刷新、重新打开：先展示**课程列表**及按 `lastOpenedLessonId` 推导出的 PB「继续收听」卡片；**不自动发声**，不恢复临时展开菜单、拖动过程、手动历史字幕滚动位置；字幕重新与有效当前句对齐并默认自动跟随。
- 页面启动/刷新在主页保持静音；普通课程、继续收听主体及播放图标进入均明确请求播放。未完成 PB 恢复有效断点，已完成 PB 从 00:00，无记录从 00:00；不会恢复 DG 作为默认音轨。
- Tesla 浏览器两组目标视口 **1256×706** 和 **773×601**：尺寸变化只使 Flutter UI 重新布局，**不得**重新实例化音频引擎、Seek、改变播放状态、课程/音轨、循环、倍速、Vocab 页状态、已保存的小窗口沉浸偏好或手动滚动意图。大窗口固定侧栏、小窗口按偏好且仅播放中可沉浸；切换到小窗口时重新开始闲置计时。
- 手动滚动字幕时暂停自动跟随但声音继续；显式「回到当前句」恢复跟随。放大/缩小窗口不等于用户主动滚动，不得取消手动阅读锚点。
- **大窗口（1256×706；当前断点宽度 ≥1000）**：字幕主区+固定右侧控制区，始终显示；取消沉浸开关、自动沉浸和「更多」按钮。原更多中的上一句/上一课/下一课/下一句、单句循环、音轨循环、自动连播、倍速、回到当前句均直接放入侧边栏；保留原 UI、主题与配色。
- **小窗口（773×601）**：标准/临时唤回时顶部紧凑导航+底部播放、进度/时间及更多；四个句/课导航按钮在更多同一行。仅沉浸偏好开启且实际播放中、无加载/错误/等待手势、菜单关闭时可闲置隐藏。隐藏后顶部和底部不保留空占位或不透明背景，字幕填满视口，**仅保留核心播放按钮，更多也隐藏**。暂停、自然停止、加载或错误时恢复控件并取消隐藏计时，持续暂停不得自动进入沉浸；恢复播放后重新开始闲置计时。按下主按钮本身不唤回/抖动；完成短按暂停后按本条恢复布局是有意的状态变化。沉浸隐藏时第一次点击字幕区域只唤回控件，消费该次点击，不 Seek、不展开词汇；控件显示后第二次明确点字幕才操作。字号自动适应，不提供手动字号和翻译。
- Tesla 浏览器进入后台、车机挂起与真实系统音频行为需**实车停车测试**；应用无法保证系统杀进程后仍继续播放。
