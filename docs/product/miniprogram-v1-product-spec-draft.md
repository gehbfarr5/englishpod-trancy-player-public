# 微信小程序首版产品规格草案
文档编号：EP-MP-PRD-001 · v0.1 DRAFT
日期：2026-10-24（北京时间）
状态：供产品审阅；不代表技术方案定稿、实现完成或设备验收通过。

## 1. 定位与已确认决策
- 面向其他英语学习者长期使用，当前优先由本人持续自用验证；之后小范围试用，再考虑推广。
- 核心学习流程：找到课程 → 完整听 Podcast → 没听懂时看台本、回听 → 继续 → 下次接着听。
- 发挥微信便捷进入、课程分享的优势；不以复刻 iOS/Android 或补齐其功能为目标。
- 每课仅 Podcast（PB）可播放；取消 Dialogue（DG）独立音频播放。
- 保留完整 Podcast 台本、Dialogue 台本和单词查看。切换三类内容不换源、不 Seek、不改变播放/暂停、不重置音频断点。
- 单词查看从来不应被视为一次音频切换。单词相关的音频操作不因“保留查看”而自动获批。
- 小程序按微信官方开发规范独立设计；现有实现只是调查对象，不是必须继承的架构。

## 3. 行为基线与优先级
1. 本轮明确确认的单音轨与内容切换规则，是小程序对原跨端基线的产品变更。
2. 其他已适用规则沿用本仓库保存的 [EP-PBC-001 v1.4](playback-behavior-contract.md)，不因重建而重新发明。
3. 官方平台事实决定可实现方式；若与产品行为冲突，先说明官方依据和实验证据、提出替代方案，再由用户决定是否改行为。
4. iOS/Android 的视觉与组件规格不约束新小程序；本文件尚未批准具体渲染器、页面栈、滚动算法或存储结构。
5. 本草案和历史规范并存期间，以本表明确解释差异；草案不自动变更其他端或已发布行为。

| 基线章节 | 小程序处理 |
| --- | --- |
| §2 普通课程列表 | PB；未完成恢复有效断点，已完成从 00:00；点击请求播放，加载中新暂停优先 |
| §2 继续收听 | 最后成功打开课程的 PB；同一活动音频不重复加载，不倒退到较旧保存点；保留基线临时 00:00 的例外规则 |
| §2 手动上一/下一课 | 单音轨 PB；00:00；继承播放/暂停；首尾手动按钮不环绕 |
| §2 切 Vocab | 扩展至三类内容：PB 台本 / DG 台本 / 单词都只切展示 |
| §2 同课 PB↔DG 及 DG 记录 | N/A：取消独立 DG 音频；不是未实现或测试失败 |
| §3.1 完成 | 正常播放跨 95% 或可信自然结束；主动 Seek 不冒充完成；完成不可被重听撤销 |
| §3.2 连播 | 默认继承手机端固定开启、下一课 PB 00:00、末课回第一课；前后台均须验证 |
| §3.2 单句/音轨循环 | 原规则保留作参考；是否进入简化首版尚待明确，不直接认定删除或批准 |
| §4 保存 | 有效断点与临时播放头分离；关键事件保存，建议约 3 秒定期保存；旧写入不覆盖新写入；打开不清零历史 |
| §5 并发与错误 | 最新用户意图优先；有限重试；失败明确提示，不偷偷跳课或换源 |
| §6 Web/Tesla 界面 | 双窗口、沉浸布局、侧栏等 N/A；不移植 |
| §6 启动与返回 | 冷启动到课程列表静音；后台已有会话返回不应套用冷启动导致停播或重载，具体生命周期待验证 |

## 4. 三部分内容的边界
- 仅 PB 时间驱动 PB 台本的播放定位；DG 台本作为阅读内容，不能拿 DG 原音轨时间戳直接定位 PB。
- 查看 DG 或单词时保持 PB 声音及播放控制状态；各内容阅读位置如何保存，待交互审阅。
- 返回 PB 台本不重新装载音频。是否自动回到当前句、是否保留手动阅读位置，尚待决定。
- PB 点句回听、上一句、快退等具体方案尚未定；不得把所有候选入口一起实现。
- DG 句子 / 单词例句若要跳回 PB，须有可验证的位置映射并获产品确认；不默认复用旧的 DG 换轨入口。
- 不因为移除 DG 播放而删除其他端音频、共享课程数据或云端资源。

工程约束（设计要求，不伪称已引用的官方原文）：

- 异步加载必须能废弃旧请求；平台限制无法满足时列清冲突，不以更多补丁掩盖。
- 存储、域名、后台音频配置、胶囊/安全区、页面生命周期逐项核验。
