# M1 单 Podcast 音轨实验方案

编号：EP-MP-REBUILD-001-M1 · v0.1 · 2026-10-24（北京时间）
状态：待官方能力核验及云测报告闭环完成后执行；本文件是用例和判定方案，不代表实验已运行。

## 目标与边界

用最少页面和一条音轨证明微信小程序上可支持的学习闭环，再决定重建架构。实验只播放 Podcast；Podcast 台本、Dialogue 台本和词汇是内容视图，不代表独立音轨。切视图不应创建/销毁/换源/seek/pause/play，也不应改动 Podcast 进度或断点。

先用短合成音频排除资源和长音频变量，再以一节经授权的真实 Podcast 音频做确认。短音频结果不能外推为长课程、锁屏或后台连播通过。

## 执行前条件

- 完成 EP-MP-REBUILD-001-M0 腾讯官方指南核验；未核验的行为保留为待确认，不据此设计规避实现。
- MiniTest API 能绑定到本次上传版本，并能够读取终态及报告；否则只执行能在现有证据链验证的部分，结果标为 BLOCKED/NOT TESTED。
- 记录候选 Git SHA、开发版版本号、微信版本、基础库、设备/系统、网络、音频样本及测试计划/任务 ID。
- 先验证开发包无旧播放器同时初始化，且没有 Dialogue 音频路径被调用。

## 用例矩阵

| ID | 场景 | 操作 | 预期 | 必要证据 |
| --- | --- | --- | --- | --- |
| M1-01 | 新课程入口 | 冷启动后从课程目录正常进入未完成课程 | 按产品规格开始 Podcast；用户未点播放前不额外产生第二次播放 | 首次 load/play 事件、页面状态、媒体位置 |
| M1-02 | 断点恢复 | 对未完成课程保存一个中间位置后退出；再次正常进入 | 恢复有效 Podcast 断点；初始化的 0 不能覆盖已保存断点 | 前后 progressJournal、load/seek 次序、实际播放位置 |
| M1-03 | 完成课入口 | 标记课程完成后正常进入 | 从 0 开始，完成事实不因位置初始化被清除 | 完成字段、resume 位置、媒体事件 |
| M1-04 | 内容视图独立 | 播放中及暂停时按 PB 台本 → DG 台本 → 词汇 → PB 台本 | 音源、播放/暂停意图、媒体位置、断点不变；没有第二个音频实例或音轨 load | 音频调用录制、断点读回；设备端播放连续性观察 |
| M1-05 | 后台/锁屏 | 播放真实课程后锁屏并等待，再回到小程序 | 依官方能力核验所得预期保持播放/系统控制；恢复后 UI 与真实媒体位置重锚，不重新赋源或跳位 | 云测/真机音频观察、后台事件、回前台状态与位置 |
| M1-06 | 后台结束与自然连播 | 播放至一课自然结束，分别验证有下一课和列表末课 | 下一课从 0 开始；末课按基线回到第一课；不得用墙钟外推伪造 ended | onEnded 来源、课程 ID 序列、新源/seek、真实声音观察 |
| M1-07 | 手动换课 | 播放/暂停时分别前进或后退课程 | 新课从 0 开始并继承 play/pause 意图；列表边界不手动循环 | 用户动作记录、源切换、进度记录 |
| M1-08 | 中断恢复 | 播放中触发系统音频打断或切后台后恢复 | 实际行为先以官方规则为准；应用 UI 不与媒体状态长期分叉，不意外重播或重复初始化 | 设备系统/微信版本、打断类型、事件顺序、媒体位置 |
| M1-09 | 资源失败与快速切换 | 模拟无效源/超时，并快速由课程 A 点到 B 再到 C | 错误可见且可恢复；最后一次用户意图生效，过期异步回调不能加载/播放旧课 | 请求/音频调用时序、错误界面、最终 lessonId 与 src |
| M1-10 | 长 Podcast 样本 | 播放代表性长 MP3 并后台运行，检查缓冲、进度保存和重进 | 不因短 WAV 通过而预设长资源行为；仅在完整数据可读时记录通过 | 样本时长/格式/URL 类型、缓冲与错误事件、真实时间位置 |

## 判定规则

- 每个用例只能记 PASS、FAIL、ERROR、NOT TESTED、BLOCKED 或 N/A，并填写判据与原始证据。
- 测试计划提交成功、开发版上传成功、没有崩溃、或界面截图看起来正常，都不等于媒体播放通过。
- 真实声音、锁屏/后台和系统中断场景必须来自具备相应观察能力的设备报告。MiniTest 若只给截图/JS 日志，相关项仍为 NOT TESTED。
- 对模拟器、真机、不同系统分开报告。未覆盖的平台不因另一端通过而继承 PASS。
- 任何 M0 官方规范与当前产品基线冲突，停止该项并记录平台条款、产品规则、复现条件及备选行为；不得在实验中自行改规则。
- 发现缺陷后先定位在资源、媒体生命周期、状态/存储或渲染同步，再修改；修复后用同一 SHA 的新构建重跑受影响项，最终报告只引用新 SHA 的证据。

## M1 架构退出条件

只有以下条件齐备后，才依据实验决定 PodcastSession、音频适配器、进度仓库和渲染器边界：

1. M0 核心官方能力有逐项证据，或明确列出有界限制。
2. 单音轨、视图独立、断点恢复与自然结束关键路径具备与目标平台相符的报告。
3. 后台、锁屏、声音和中断能力分别说明“已验证”或“平台/云测无法观测”。
4. 长 Podcast 样本单独通过或记录为实现阻塞。
