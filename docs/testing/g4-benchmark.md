# G4 离线测量与比较工具（#4 / #6）

此工具准备采样和验收材料，不运行微信、不调用模型、不连接设备，也不生成产品性能数据。它没有替代 PR #92 的原生回归。当前仍缺微信真机基线；G4 未完成。

## 运行

只需 Python 标准库，从仓库根目录执行：

```bash
python3 -m unittest discover -s pipeline -p 'test_g4_benchmark.py' -v
python3 pipeline/g4_benchmark.py baseline.json
python3 pipeline/g4_benchmark.py baseline.json after.json
```

退出码：0 = 样本齐备且所填回归状态通过，可交给审查；1 = 样本不足、指标不可用、存在失败或回归未通过；2 = 输入无效或前后条件不匹配。`READY_FOR_REVIEW` 不是性能收益、真机通过或 G4 通过，输出始终含 `g4_acceptance=NOT_ASSESSED`。

使用 [空白模板](g4-benchmark-template.json)。模板故意无设备、SHA 或测量值，直接运行应拒绝，不能把模板或测试中的合成数据当产品证据。填入实际环境后，每个文件只容纳一个条件和一次测试构建，所有尝试都保留；超时和失败不能从分母删除。每次尝试使用唯一 ID，失败填 `status=FAIL`，未取得的指标填 `null` 或省略，不能填 0 代替。

`samples` 中每项结构为 `{"id":"attempt-001","status":"FAIL","metrics":{}}`。成功尝试将 status 改为 PASS，并在 metrics 填下表中对应 suite 的指标名及实际数值；没有取得的指标仍保持缺失。失败原因、采样时钟/观察窗口、截图和执行步骤放在伴随验收记录，不能把原始日志或任意字段塞入此 JSON。

`environment` 必须记录精确源码 SHA、构建身份、平台、设备、OS、客户端、渲染 runtime、网络、冷/热缓存、课程/fixture 版本、课程数、场景和证据层级（L0/L1/L2/physical）。`network` 应区分 Wi-Fi/蜂窝、限速配置和网络会话；不填 SSID、IP、位置或凭据。`fixture` 应能追溯课程索引与测试进度集版本；不含用户真实学习记录。`scenario` 标明入口与 PB/DG 等条件。

同条件每项指标至少取得 5 个成功样本；输出逐项 n、中位数、最小值、最大值以及总尝试数、失败数和失败率。失败样本中的部分时间不参与成功延迟统计，但失败次数保留。采样超过 5 次时保留全部预先规定的尝试，不为得到好看的中位数挑样本。

前后比较只允许 SHA 和 build 不同，其余条件必须完全一致。正的 `median_delta` 表示数值增大；百分比以 before 为分母，基线为零或任一侧少于 5 个有效指标值时不计算。没有自动收益阈值，也不作显著性判断。零失败和功能回归通过只是进入审查的必要条件；审查仍需原始逐次记录、执行方法、截图/实际交互以及预先确定的用户收益标准。

## A：first_content（#4 / #59）

当前源码依据：main@83a9fa4，`miniprogram/pages/player/index.ts`。索引与详情请求重叠，详情准备后在音频加载前等待索引，不能将两者耗时简单相加。不要为了采样移除保护文件 ID 正确性的等待。

所有 `_ms` 均为**同一次尝试、同一个时钟、相对播放器 onLoad 起点的时间**，不能混用阶段耗时或来自不同进程的绝对时钟：

| 指标 | 观测边界 |
| --- | --- |
| index_ready_ms | 当前 adapter 的索引就绪 |
| detail_ready_ms | 课程详情取得且本地准备完成，进入索引等待前 |
| transcript_ready_ms | 台本 setData 的完成回调；仅是可观测的下发完成代理，不证明屏幕像素已绘制 |
| audio_load_ms | 调用实际音频 adapter.load 的时刻 |
| canplay_ms | 对应本次课程/音轨 load 的 onCanplay 回调 |
| play_ms | 对应本次课程/音轨 load 的 onPlay 回调 |

分别采冷与热条件；明确索引存储、详情内存和音频缓存的重置/保留办法，不删除个人进度。使用可隔离的开发环境，避免把前一次请求回调计入下一次。开发者工具 L1 与 iPhone physical 分开。代理回调不等于第一声可听音频；真正出声需另外保存有误差说明的人工/音频观测，不能写入 play_ms 冒充精确听感数据。

与基线同时执行回归：快速 A→B 切课及旧响应晚到、切 PB/DG、加载期点击播放/暂停的反馈、失败重试、退出后晚到回调。记录最终课程/音轨、播放意图和进度是否正确。`regression_status` 只能根据实际逐场景结果填写；未跑为 NOT_TESTED。工具不替运行者断言这些交互已经通过。

## B：catalog（#6）

当前源码依据：main@83a9fa4，`miniprogram/pages/library/index.ts`。已有 CHUNK_SIZE=30 增量追加；完整 filtered models 与 visibleLessons 仍先生成/下发。这些是源码事实，不是卡顿实测。

| 指标 | 观测边界 |
| --- | --- |
| model_build_ms | 一次课程库视图模型计算的耗时 |
| first_render_ms | 刷新开始至首批课程 setData 完成的代理耗时 |
| filter_ms | 指定筛选动作开始至对应 setData 完成的耗时 |
| scroll_expand_ms | 指定触底扩展开始至新增课程 setData 完成的耗时 |
| payload_bytes | 对上述指定一次刷新所有 setData patch 按 UTF-8 JSON 编码的字节总数；不是实际网络流量 |
| peak_memory_bytes | 固定观察窗口、指定工具实际读到的峰值；注明 JS heap 或进程内存，不能混用 |

对 30 与 335 课分别采集，使用等价的匿名标题/进度分布和固定筛选/触底步骤，禁止修改生产 CloudBase 数据。两种规模是不同条件，分别生成报告，不能通过 before/after 命令把规模变化说成代码优化。真正代码前后比较时，每个规模各有独立的一对文件。

渲染 FPS/帧时序、组件数量、setData 次数、滚动位置和触控行为作为伴随证据保留；工具不从 JS 模型耗时推导流畅度。运行环境无法读取内存时填 null，报告保持不完整，并明确该缺口，不能用主机 Python/Node 内存冒充微信内存。

回归至少包含 All/In Progress/Completed、空筛选、继续收听和进度投影、已滚动列表切换筛选再返回、触底扩展后的课程点击。先用测量定位模型计算、桥接或挂载组件的成本，收益不充分时记录暂缓，避免预先决定虚拟化重构。
